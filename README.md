## Security and privacy

Public GitHub content must never contain:

- API keys, access tokens, OAuth client secrets or refresh tokens
- private keys, certificates, signing secrets or service-account credentials
- database credentials, production connection strings or environment files
- supplier, payment-provider or webhook secrets
- customer/order data, private analytics exports or internal logs
- private infrastructure addresses, internal-only endpoints or confidential runbooks

Example configuration, when published, must use placeholders only. Secret scanning should be run before public release. If a credential is ever committed, it must be treated as compromised and rotated before repository-history cleanup.

## Repository model

Public portfolio/documentation repositories explain the products and engineering work. Production repositories stay private by default. This separation gives partners, clients, recruiters and collaborators a useful view of the work while preserving the security boundary of live systems.
